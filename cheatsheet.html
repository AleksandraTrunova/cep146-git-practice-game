CLI & Git Reference Guide

Review syntax rules, command options, and operational behaviors across all 4 levels.

LEVEL 1: Workspace Setup, Navigation, & Identity

Interact with the local file system, configure global environments, and initialize empty instances.

pwd

Print Working Directory

Outputs the absolute structural path of your current active location inside the terminal system directory tree.

mkdir <folder_name>

Make Directory

Generates a brand new, empty folder configuration block at your current pathway directory location.

Example: mkdir git-game

cd <target_path>

Change Directory

Shifts your active command line pointer location to jump into a separate targeted folder path resource.

Tip: Run cd .. to step backward up out of your current directory.

git config --global user.name / email

Git Configuration

Configures your global developer credentials. These metrics sign all your future local timeline commits with authorship metadata records.

Example: git config --global user.name "My Name"

git init

Initialize Repository

Converts a plain directory into an active tracking workspace by setting up a hidden internal validation database structure named .git/.

LEVEL 2: Tracking Changes, Inspecting Diffs, & Local Commits

Manage the staging framework pipeline, review incremental differences, and capture historical timeline snapshots.

touch <filename>

Create Blank File

Generates a fresh, empty tracking file structure inside the workspace directory folder path if the name does not already exist.

git status

Check Status

Runs a real-time structural analysis of your workspace, categorizing items into modified files, untracked changes, or ready-to-commit staged packages.

git diff

View Differences

Renders line-by-line character transformations, comparing unstaged working modifications against your last stable repository commit state baseline.

git add <file>

Stage Changes

Elevates directory changes into the secure Staging Area container box, grouping them into a single bundle prepared for history mapping.

Tip: Execute git add . to package every modification inside your local folder recursively.

git commit -m "<message>"

Record Snapshot

Seals staged changes into a permanent milestone tracking node in the repository timeline. The -m flag attaches an explicit inline summary log string.

git log

View Commit History

Generates an ordered chronological output list mapping all previously saved commit snapshots, showing hashes, authors, dates, and logs.

LEVEL 3: Advanced Branching, Context Switching, & Conflict Interventions

Isolate experimental features via independent branch tracking pathways and safely intercept collision points.

git branch <branch_name>

Manage Branches

Creates an isolated development tracking line pointer pointing to your active commit base. Run git branch standalone to output local branch listings.

git checkout <branch>

Switch Context

Redirects the system shell tracking focus onto an alternate target timeline branch structure.

git switch <branch>

Modern Switch Alternative

A modern, dedicated utility built exclusively to execute branch shifts cleanly, separating branch actions from old file restoration behaviors.

git merge <target_branch>

Merge Timelines

Integrates historical development snapshot nodes from a target feature branch into your active branch context line.

git merge --abort

Reset

Intercepts a blocked merge conflict state, dropping the compilation instantly and resetting all working files to their clean, pre-merge condition.

LEVEL 4: Remote Repositories & Cloud Collaboration

Link local environments to host endpoints and synchronize data arrays across machine contexts.

git clone <url>

Clone Remote Repo

Downloads a complete local repository copy from a hosted server URL address, instantly recreating history maps and linking background default tracking paths.

git remote add <short_name> <url>

Link Cloud Target

Registers an explicit structural map link connecting your local project configuration up to a cloud server URL using an accessible shortcut name like origin.

git push <remote_name> <branch>

Upload Commits

Uploads verified local branch commit sequences up to the matched cloud server repository target branch directory tracking slots.

git fetch <remote>

Download Metadata

Downloads updated metadata records, hash points, and branch details from the cloud server box **without changing or overwriting** any active local file assets.

git pull <remote> <branch>

Fetch & Merge Updates

Pulls down changes from the server database and instantly merges them into your active local working directory files. Acts as a combined sequence tracking chain of fetch + merge.
